# 政务知识问答 —— 权限感知 RAG 试点原型

这是 [`docs/政府级RAG改造方案.md`](../docs/政府级RAG改造方案.md) 中 **P0 试点** 的可运行切片：在原有 LangChain 教学项目之上，增加了**文档级权限、密级标签、检索前裁剪、拒答与审计**。

它同时解决了一个实际问题：Qoder 内置终端没有输入法，无法输入中文；改用浏览器后中文输入恢复正常。

> 定位：验证「权限与审计应该放在链路的哪个位置」，不是生产系统。未实现的 P1/P2 能力见文末。

## 能力一览

| 能力 | 实现方式 |
|---|---|
| 登录（演示） | 选择账号 + 演示口令；服务端签发带 `jti` 的签名 Cookie（HttpOnly、SameSite=Lax），连续 5 次失败锁定 30 分钟 |
| 会话管理 | 有效期 8 小时由**服务端**校验；登出即吊销（进程内 jti 黑名单），旧 token 不能重放 |
| 文档级 ACL | `can_view()` 纯函数 + FAISS `filter` + BM25 语料裁剪，裁剪后再进入生成上下文 |
| 密级标签 | 语料 front matter 标注 公开 / 内部 / 秘密，入库即带 `classification_level` |
| 混合检索 | 复用 `main.py` 的 FAISS + jieba BM25 + 手写 RRF |
| 多轮对话 | 复用 `main.py` 的追问改写（`condense_question`）与最近 3 轮历史 |
| 流式输出 | SSE 推送结构化事件，逐 token 渲染，跨分片 `<think>` 过滤 |
| 引用来源 | 每个回答附带文档标题、部门、密级、生效日期、切片预览 |
| 拒答 | 无可见文档 / 相关性不足 → 直接拒答，**不调用生成模型** |
| 审计 | 问答、登录/失败/锁定、登出、清空会话均落 JSONL；问答前做可写性预检（fail-closed） |

## 快速开始

前置条件与根目录 README 相同：Ollama 已启动，已拉取生成模型与 embedding 模型。

```bash
# 1. 安装依赖（已包含 fastapi / uvicorn / itsdangerous / pyyaml）
uv sync

# 2. 准备配置：演示口令与（建议）固定的会话密钥
cp .env.example .env
#    编辑 .env：
#      DEMO_PASSWORD=demo-2026        # 演示口令，所有账号共用；可用 DEMO_PASSWORD_WANG 单独覆盖
#      SESSION_SECRET=<随机长字符串>  # 留空则每次启动随机生成，重启后需重新登录

# 3. 启动服务（在仓库根目录执行）
uv run uvicorn app.server:app --host 127.0.0.1 --port 8000

# 4. 浏览器打开
#    http://127.0.0.1:8000
```

> 认证强度说明：演示口令只是把「点一下就能进」变成「需要知道口令」，
> 不构成生产级认证。真实部署必须对接统一身份认证，并开启 HTTPS + `secure` Cookie。

首次问答时会加载语料、校验索引指纹并构建 `web_index/`（12 个切片，几秒钟）。语料或切分配置变化会自动重建，无需手动删索引。

> 当前机器实测环境：Ollama 本地 `qwen3:4b`（生成）+ `bge-m3`（嵌入），全部跑在 GPU 上。
> 若使用默认的 `deepseek-r1:1.5b`，回答质量会明显下降，但流程一致。

## 界面

前端是单文件 `app/static/index.html`，不加载任何外部字体、图标或脚本，断网内网均可使用。整体按政务服务门户的视觉习惯设计：

- **版式**：顶部 3px 政务蓝条 + 白色报头，正文使用衬线标题与无衬线正文；直角、1px 细边框，不用圆角卡片和聊天气泡。
- **登录页**：左侧系统说明（访问控制 / 检索原则 / 审计留痕），右侧演示账号表格（姓名、部门、职务、最高密级、操作）。会话过期时自动回到此页并在顶部说明原因。
- **问答页**：左侧 300px 信息栏展示当前身份与可见文档清单（含密级标签），右侧为问答区；回答以「答」卡片承载，左侧 3px 竖线标注，引用依据按 `[序号] 标题 + 密级 + 部门/文号/生效日期 + 预览` 列表展示；预览去掉 Markdown 标记，只留纯文本。
- **流式交互**：生成中显示「停止生成」，可中断并保留已输出内容（标注「已停止生成」）；滚动跟随只在用户位于底部时生效，上翻阅读时不被抢滚动，右下角提供「回到底部」。
- **回答操作**：每条回答底部显示完成耗时、引用段数与时间，并提供「复制回答」；问答区顶部提供「打印」，打印样式隐藏导航、信息栏与输入区，只保留问答正文和引用。
- **状态区分**：拒答为琥珀色卡片并注明原因与可见文档数；接口异常为红色卡片；正常回答底部显示耗时与引用段数。会话过期（401）自动回登录页，网络中断与服务未就绪给出中文提示，不使用浏览器 `alert`。
- **密级标签**：公开（绿）/ 内部（蓝）/ 秘密（红）三色徽标，文字始终与颜色同时出现，不单靠颜色传达信息。
- **响应式**：≤860px 时隐藏左侧信息栏，身份摘要并入问答区顶部；账号表改为纵向堆叠（`data-label` 生成字段名），示例问题横向滚动；无横向溢出。高度使用 `100dvh` 并适配底部安全区；触屏上不自动聚焦、回车即换行，打印按钮隐藏。
- **可访问性**：跳转链接、`:focus-visible` 焦点环、问答记录区 `role="log"`，流式期间设置 `aria-busy`，检索/完成/拒答经 `aria-live` 播报，支持 `prefers-reduced-motion`。

## 权限模型

```
可见 ⇔ 切片密级 ≤ 用户密级 且（密级 = 公开 或 切片部门 = 用户部门）
```

实现上有三个关键点：

1. **越权内容不进生成上下文**。FAISS 传 `filter` 回调，BM25 的语料也只由可见切片构建。
   需要说明的是：LangChain 的 FAISS `filter` 是**检索后过滤**（先 ANN 取 `fetch_k` 个候选，
   再按 metadata 过滤），因此 `fetch_k` 取全集大小，才能保证裁剪后候选充足。
   这保证了密级内容不会进入 Prompt，但**不等于索引层分区**——规模上量后单次查询会线性变慢，
   生产应改为按密级/部门分索引（方案 §4.2）。
2. **fail-closed**。切片缺少 `classification_level`、或密级值不是整数时，一律视为不可见。宁可拒绝，不可放行。
3. **权限与索引解耦**。索引只存元数据，权限规则在每次请求时实时计算。
   但注意：语料与用户表都在进程启动时加载，**修改 front matter 的部门/密级或 `users.py` 后需要重启进程才生效**，
   并非「改完立即生效」。

## 拒答与阈值校准

拒答分三种情况：

| 情况 | 判定 | 是否调用 LLM |
|---|---|---|
| 用户没有任何可见文档 | `visible_chunks == 0` | 否 |
| 稠密检索无结果 | `no_dense_hits` | 否 |
| 最佳命中 L2 距离 > 阈值 | `low_relevance` | 否 |

阈值 `RAG_MAX_DISTANCE` 默认 **0.78**，用 bge-m3 在本语料上实测校准（2026-10-29）：

| 类型 | 问题示例 | 可见用户 | 最佳 L2 距离 |
|---|---|---|---|
| 应回答 | 政务服务中心的办公时间？ | 张伟 | 0.393 |
| 应回答 | 差旅住宿费标准是多少？ | 王强 | 0.580 |
| 应回答 | 年休假有几天？ | 李娜 | 0.632 |
| 应回答 | 数据外发需要什么审批？ | 陈静 | 0.672 |
| 应拒答（越权） | 数据外发需要什么审批？ | 李娜 | 0.905 |
| 应拒答（越权） | 生病请病假要什么证明？ | 王强 | 0.979 |
| 应拒答（越权） | 年休假有几天？ | 张伟 | 1.072 |
| 应拒答（越权） | 口令有什么要求？ | 张伟 | 1.194 |
| 应拒答（越权） | 差旅住宿费标准是多少？ | 张伟 | 1.260 |
| 应拒答（无关） | 如何申请公租房？ | 王强 | 0.945 |
| 应拒答（无关） | 今天天气怎么样？ | 王强 | 1.070 |
| 应拒答（无关） | 单位今年科研项目立项情况？ | 张伟 | 1.180 |

观测到的可回答区间是 ≤ 0.672，应拒答区间是 ≥ 0.905，因此 0.78 位于窗口中部。

**注意**：L2 距离与 embedding 模型的向量尺度强相关。换 embedding 模型、换语料或换切分参数后，必须重新校准；演示前务必按上表跑一遍。临时调整：

```bash
RAG_MAX_DISTANCE=0.85 uv run uvicorn app.server:app --port 8000
```

## 审计日志

问答、登录/失败/锁定、登出、清空会话都落一行 JSON 到 `logs/audit.jsonl`（已 gitignore）：

| `event` | 触发时机 |
|---|---|
| `chat` | 每次问答结束（正常/拒答/异常/客户端中断都会落一条） |
| `auth.login` | 登录成功、口令错误、因失败次数过多被锁定 |
| `auth.logout` | 登出（同时吊销服务端会话） |
| `history.clear` | 清空会话历史 |

```json
{
  "ts": "2026-10-29T12:18:09+08:00",
  "event": "chat",
  "status": "ok",
  "error": null,
  "request_id": "…",
  "user": "wang",
  "dept": "财务处",
  "max_level": 2,
  "ip": "127.0.0.1",
  "question": "差旅住宿费标准是多少？",
  "rewritten_query": "差旅住宿费标准是多少？",
  "refused": false,
  "refusal_reason": null,
  "visible_docs": ["gov-001", "gov-003"],
  "citations": [{"chunk_id": "gov-003#1", "doc_id": "gov-003", "classification": "秘密", "dept": "财务处"}],
  "answer": "……",
  "elapsed_ms": 7822,
  "llm": "qwen3:4b",
  "embed_model": "bge-m3"
}
```

`status` 取值：`ok` / `refused` / `error`（异常，同时 `error` 字段记录异常类型与消息）/ `cancelled`（客户端停止或断开）。
`ts` 带本机时区偏移；写入后默认 fsync（`AUDIT_FSYNC=1`），进程崩溃不会丢掉已返回问答的记录。

问答开始前会先做审计可写性预检：审计通道不可用时直接 503，不进入「有问无痕」状态。

回答按网络安全法第 21 条留存 ≥ 6 个月属于部署要求；本原型只负责「写」，归档、防篡改、独立加密存储属于 P1。

## HTTP 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/` | 单页前端 |
| GET | `/api/users` | 演示账号列表（仅姓名/部门/职务，不含密级；真实系统删除此接口） |
| POST | `/api/login` | `{"username": "wang", "password": "…"}`，签发会话 Cookie；口令错误 401，连续失败锁定 429 |
| POST | `/api/logout` | 吊销服务端会话并清除 Cookie（旧 token 立即失效） |
| GET | `/api/me` | 当前用户 + 可见文档 + 运行参数 |
| POST | `/api/chat` | `{"question": "…"}`，返回 SSE；响应头带 `X-Request-Id` 便于对账审计 |
| POST | `/api/history/clear` | 清空当前用户的会话历史 |
| GET | `/api/health` | 服务状态；未就绪（语料/索引未加载）返回 **503** |

SSE 事件类型：

| 事件 | 含义 |
|---|---|
| `rewrite` | 多轮追问被改写为独立问题 |
| `citations` | 命中的引用片段（含密级） |
| `token` | 增量答案文本 |
| `done` | 完成，携带完整答案、引用与耗时 |
| `refusal` | 拒答，携带原因、可见文档数、最佳距离 |
| `error` | 异常 |

## 已知限制

| 限制 | 说明 | 对应方案 |
|---|---|---|
| 演示口令非生产认证 | `DEMO_PASSWORD` 为共享口令，仅把「点选即登录」提升到「知道口令」；无 MFA、无实名 | P0 对接 SSO |
| 会话吊销只在进程内 | jti 黑名单存在内存，多副本部署需换 Redis 等共享存储；`SESSION_SECRET` 未配置时各进程密钥不同 | P1 会话存储 |
| Cookie 未开 `secure` | 内网 HTTP 演示需要；HTTPS 部署必须开启 | P0 部署 |
| 历史存内存 | 单进程、重启即丢；多副本不共享 | P1 会话存储 |
| 无内容安全过滤 | 输入输出敏感词、提示注入防护未做 | P1 |
| 无 Rerank / 评测集 | 相关性只靠 L2 阈值，召回质量有限；阈值仅由 12 条样本校准 | P1 |
| 审计仅本机 JSONL | 含明文答案，无轮转/防篡改/异地留存；需配合文件权限与独立备份 | P1 |
| 问答无限流 | 登录已限速，但问答接口没有并发/频率限制与超时降级 | P1 |
| 引用不能点击回源 | 只返回预览片段，答案正文也未标注 `[n]` 编号 | P0 完整版 |
| 单进程建索引 | 多副本需要共享向量库或独立构建；索引目录可写即等同于代码执行（pickle） | P2 |

完整的差距清单、目标架构与分期路线见 [`docs/政府级RAG改造方案.md`](../docs/政府级RAG改造方案.md)。

## 故障排查

| 现象 | 原因与处理 |
|---|---|
| 页面提示「服务初始化失败 … 503」 | Ollama 未启动，或 `.env` 中的模型未拉取；先运行 `ollama serve` 并 `ollama pull` |
| 换了知识库但答案还是旧的 | `web_index/index.meta.json` 指纹不匹配会自动重建；若仍异常，删除 `web_index/` 后重试 |
| 所有问题都被拒答 | 阈值过严（`RAG_MAX_DISTANCE` 太小），按上表重新校准 |
| 重启后登录态失效 | 未设置 `SESSION_SECRET` 时会话密钥随机生成；生产环境从密钥管理系统注入 |
| 登录返回 429 | 同一账号连续 5 次口令错误，已锁定 30 分钟（见响应头 `Retry-After`） |
| 问答返回 503「审计通道不可用」 | `logs/` 不可写（磁盘满/权限变更）；按合规要求此时不提供问答 |
| 终端 curl 发中文报 400 | Git Bash 会转码参数；把 JSON 写入 UTF-8 文件后 `--data-binary @file` |

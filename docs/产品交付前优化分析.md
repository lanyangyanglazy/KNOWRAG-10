## 0. 一句话判断

当前系统是**扎实的检索内核 + 政务试点雏形**，工程底子好（混合检索、多轮改写、流式、ACL + 审计），但**产品外壳（管理 UI、权限体系、部署、文档解析、溯源、评测）几乎空白**。

小团队不和大厂开源平台拼"功能广度"，要拼**轻量私有化 + 检索准 + 合规内置**的纵深。

---

## 1. 产品定位与目标客户

核心策略：**垂直、轻量、合规/隐私刚需**——这是 Dify / FastGPT / RAGFlow 这类"通用平台"最难下沉、也最难进场（需上云）的象限。

| 场景 | 典型客户 | 为什么是我们能赢 | 优先级 |
|---|---|---|---|
| **① 政务 / 国企内网知识库** | 委办局科室、国企职能部 | 现状已有政务原型（文档级 ACL + JSONL 审计 + 离线 Web UI），**合规基因现成**；大厂 SaaS 要上云、数据出域，强监管场景进场难。我们"私有化 + 可审计 + 按密级裁剪"直接命中刚需 | P0 首选 |
| **② 中小企业私有化知识库** | 制造业 / 贸易 / 服务业（50–500 人）IT 负责人 | 用本地 Ollama 即可跑，**无 API 成本、数据不出公司**；对比 Dify / FastGPT 私有化是"全家桶"（重、需工程能力），我们"一键部署 + 开箱问答"降低门槛，走量 | P0 / P1 |
| **③ 专业机构合规助手**（律所 / 咨询 / 医疗） | 律所合伙人、咨询公司、民营医院 | 同样隐私 / 合规驱动，且要"答案带条文引用、可追溯"。可作为 ①② 的延伸垂直包，不必单独重投入 | P2 备选 |

**一句话定位**：面向强合规、强隐私场景的**轻量私有化企业知识问答**——*装得进内网、答得准、查得到来源、留得下审计*。

---

## 2. 核心卖点 / 差异化

| 竞品 | 他们的强项 | 他们的软肋（我们的切口） |
|---|---|---|
| **Dify** | 低代码 LLMOps 平台、工作流 / Agent 全家桶 | RAG 只是模块之一，**检索质量不是第一优先级**；私有化部署重；偏"平台"需配置能力 |
| **FastGPT** | 知识库问答 + 工作流成熟 | 仍走"平台 / SaaS"思路，私有化较重、功能大而全 |
| **RAGFlow** | 深度文档理解、排版解析强 | 依赖模型（layout 解析）、**部署资源要求高**、面向复杂文档重场景 |

**我们的差异化（凭什么赢）：**

1. **检索质量优先 + 中文友好**：FAISS 稠密 + BM25 稀疏 + RRF 融合 + jieba，专注"答得准"而非"功能多"——RAG 核心价值就是答得准，很多平台答不准。
2. **极致轻量 + 真私有化**：单 FastAPI 服务 + 本地 Ollama，无外部依赖、无 API 成本、数据不出域。竞品的私有化是"全家桶"，我们是"单点轻量"。
3. **合规内置（政务基因）**：文档级 ACL + 审计日志**已现成**，天然适配强监管；这是 SaaS 难进场、小团队能差异化的点。
4. **可解释 / 可追溯**：答案展示引用来源与检索路径，政务 / 专业场景要"说得清出处"。
5. **聚焦单点而非平台**：不做工作流编排、不做 Agent 市场，把"企业内网知识问答"做到极致。

**坦诚的风险**：生态、社区、多模态、复杂文档解析深度不如 RAGFlow。差异化必须死守"轻量 + 合规 + 检索准 + 私有化"象限，不越界拼平台。

## 3. 用户故事

1. **政务科室文员**：作为文员，我上传一份机密文件并设定密级 / 可见部门，这样同事提问时只会看到自己权限内的内容，避免越权泄露。
2. **中小企业 IT 负责人**：作为 IT，我在一台内网服务器上 docker 一键部署并接入本地 Ollama，这样员工不用任何训练就能在浏览器里问公司制度。
3. **企业员工（最终用户）**：作为员工，我问"年假怎么算"，系统基于内部制度文档给出**带引用来源**的答案，并能继续追问澄清。
4. **合规 / 审计人员**：作为审计，我导出 JSONL 审计日志，复盘谁、何时、问了什么、系统返回了哪些文档，用于合规检查。
5. **律所助理**：作为助理，我把判例 / 法规导入后提问，得到带条文引用的答复，降低低级检索遗漏。

## 4. 需求池（P0 / P1 / P2）

### P0 — 卖出去必须有的（MVP 关门条件）

| 编号 | 功能 | 验收标准 |
|---|---|---|
| P0-1 | **多格式文档解析与知识库管理 UI** | 支持 pdf/docx/txt/md 上传；Web 界面可增删 / 分类 / 查看索引状态；非命令行操作 |
| P0-2 | **用户 / 角色权限体系** | 支持账号登录 + 角色（管理员 / 普通用户）；与现有文档级 ACL 打通，越权查询返回空集 |
| P0-3 | **一键私有化部署** | 提供 Docker Compose + 配置文档，IT 人员 30 分钟内可在内网拉起；含 Ollama 本地模型指引 |
| P0-4 | **答案引用溯源** | 每个回答标注来源文档 / 片段，前端可点击展开原文；无来源时不编造 |
| P0-5 | **检索质量基准（中文 eval）** | 提供 ≥ 50 条中文问答测试集，关键场景准确率 ≥ 85%，作为"答得准"的量化证明 |
| P0-6 | **审计日志完善** | JSONL 记录 用户 / 时间 / 问题 / 命中文档 / 答案摘要；可导出 |

### P1 — 竞争力（差异化护城河）

| 编号 | 功能 | 验收标准 |
|---|---|---|
| P1-1 | **检索调优面板** | 可配置 chunk 大小、相似度阈值、RRF 权重，并即时看到效果变化 |
| P1-2 | **多知识库 / 多租户隔离** | 不同部门 / 客户知识库物理或逻辑隔离，互不可见 |
| P1-3 | **对话历史持久化 + 导出** | 会话可保存、回溯、导出为文本 |
| P1-4 | **答案质量反馈（数据飞轮）** | 点赞 / 点踩 + badcase 收集入口，可导出用于迭代 |
| P1-5 | **模型热切换 UI** | 界面切换 Ollama / DeepSeek，无需改配置重启 |
| P1-6 | **安全加固** | 防 prompt injection 基础过滤 + 输出内容审核 |

### P2 — 锦上添花

| 编号 | 功能 | 验收标准 |
|---|---|---|
| P2-1 | **文档自动摘要 / 标签** | 导入时自动生成摘要与标签，便于检索与浏览 |
| P2-2 | **IM 入口（企微 / 钉钉机器人）** | 在 IM 中 @机器人 即可问答，复用同一检索内核 |
| P2-3 | **移动端 / 小程序适配** | 核心问答在移动端可用 |
| P2-4 | **可视化检索过程** | 展示命中文档 / 相似度热力，辅助排查答不准 |
| P2-5 | **知识库健康检查** | 标记过期 / 低覆盖内容，提醒补充 |

## 5. Go-to-Market / 定价思路

- **商业模式**：开源核心版（GitHub 建信任、攒口碑）+ 商业企业版（私有化部署包 + SSO / 多租户 / 合规增强 + 支持服务）。小团队忌"持续运营重 SaaS"，建议**一次性授权费 + 年维护费**。
- **定价**：按"部署实例 / 知识库规模 / 坐席"阶梯报价；企业版年维护费约为授权费的 15–20%。避免纯订阅带来的持续运维负担。
- **渠道**：政务 / 国企走**集成商 / 渠道代理**（他们有资质与关系）；中小企业走官网 + **试用镜像（docker 一键体验）** 自获客。
- **关键抓手**：做一套**"政务合规演示包"**（脱敏样例数据 + 10 分钟看到价值），作为销售标准武器。
- **灯塔客户**：先打 1 个政务科室 + 1 家制造企业做标杆案例，再复制。

## 6. 待确认问题（需拍板的关键决策点）

1. **首选目标市场**：政务 / 中小企业 / 专业机构，谁排第一？直接决定 P0 重心（如政务必做 SSO）。
2. **纯私有化 vs 轻 SaaS**：是否坚持离线 / 内网，还是也提供托管版？影响合规卖点与架构。
3. **商业化路径**：开源引流 vs 闭源收费？影响社区建设 vs 短期收入。
4. **知识库规模预期**：客户库是百 MB 级还是 GB 级？GB 级需考虑换型向量库（如 Milvus），而非 FAISS 单机。
5. **LLM 默认策略**：捆绑本地 Ollama（零成本叙事）还是主推客户自带 API？影响部署复杂度。
6. **SSO / 多租户是否进 P0**：政务 / 国企基本必选，需确认是否首发。
7. **是否把 IM 入口（企微 / 钉钉）列为早期卖点**：影响 P1 排期。

---

## 结论

当前系统"**内核强、外壳弱**"。卖出去的最短路径 = **守住政务 / 中小企业私有化合规场景，先补齐 P0（管理 UI + 权限 + 部署 + 溯源 + 中文 eval + 审计），用"轻量私有化 + 答得准 + 可审计"三张牌差异化切入**，避开与大厂开源平台的功能军备竞赛。
